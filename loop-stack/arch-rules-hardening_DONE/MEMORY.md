## Learnings
- [arch-rules-hardening, task 1] Removing UI-coupled appearance synchronization from `Config._load_settings` and moving it to UI initialization (`window_setup.py`) completely decouples the Core layer from UI imports while preserving macOS first-run dark mode detection.
- [arch-rules-hardening, task 1] Hardening AppleScript invocations against hanging deadlocks and string injection requires explicit character escaping (doubling backslashes, escaping double quotes, stripping carriage returns and newlines) and bounding subprocess execution with `timeout=3.0` while catching `TimeoutExpired` to prevent UI thread freezes.
- [arch-rules-hardening, task 1] Preserving clean backward-compatibility re-export shims when moving models and components across architectural layers (e.g. `src.core.tray -> src.ui.components.tray_icon`, `src.domain.update_models -> src.core.update_models`) prevents breaking existing callers while establishing strict top-down layer dependency (`UI -> Services -> Domain -> Core`).
- [arch-rules-hardening, task 2] Refactoring high-arity function signatures (>6 parameters) into frozen domain dataclasses (`HistoryRecord`, `DownloadJobConfig`, `AttemptContext`, `WindowDependencies`) with legacy arg unpacking helpers (`_unpack_legacy_add_entry`, `_unpack_legacy_config`, `_unpack_legacy_deps`) enforces parameter limits (<= 6) while maintaining 100% backward compatibility across callers and tests.
- [arch-rules-hardening, task 2] Python runtime at `.venv\Scripts\python.exe` is a working Python 3.11 environment with pytest 9.1.1; running with `--basetemp=.pytest-temp-verify` cleanly executes all 65 test cases without Windows temp path permission errors.
- [arch-rules-hardening, task 3] In AST analysis of function parameters, counting posonlyargs, args, kwonlyargs, vararg, and kwarg while explicitly popping any leading 'self' or 'cls' receiver parameter precisely flags functions violating parameter budgets (max 6) without false positives on standard methods.
- [arch-rules-hardening, task 3] CI release workflows require SHA-256 integrity verification (`Get-FileHash -Path "ffmpeg.exe" -Algorithm SHA256`) against known-good binary hash (228D7A8556258DE907FDB55F36850078EBC7680B84EC30D84EA02E99BEC1D1EB) to prevent compromised binaries from leaking into distribution packages.
- [arch-rules-hardening, task 4] Supporting optional parameter defaults (`record_or_url: HistoryRecord | str | None = None`) in legacy unpacking adapters ensures seamless backward compatibility when callers supply the primary identifier via keyword argument (e.g. `url=...`) rather than positional argument.
- [arch-rules-hardening, task 4] Verifying cross-layer decoupling requires static AST import auditing of internal source files, as backward-compatibility re-export shims can silently mask residual inverted imports if callers or tests continue targeting legacy paths.
