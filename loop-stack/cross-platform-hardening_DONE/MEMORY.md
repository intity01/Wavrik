## Learnings
- [cross-platform-hardening, task 1] When bundling Python GUI apps with `pythonw.exe` or running headless environments, `sys.stdout` can be `None`; guarding `logging.StreamHandler(sys.stdout)` with `if sys.stdout is not None:` prevents `AttributeError` during runtime initialization.
- [cross-platform-hardening, task 1] PyInstaller 6 onedir layout stores collected binaries under `_internal` while onefile extracts to `sys._MEIPASS`; checking `application_root() / exe`, `resource_root() / exe` (checking `_MEIPASS`), and `application_root() / "_internal" / exe` provides robust binary resolution across frozen packages, source trees, and development runs.
- [cross-platform-hardening, task 1] Native downloader and runtime binary resolution must branch on `sys.platform == "win32"` to determine executable extension (`ffmpeg.exe` vs `ffmpeg`) before fallback to `shutil.which`.
- [cross-platform-hardening, task 1] Blocking shell execution of downloaded files requires including POSIX script and executable extensions (`.sh`, `.command`, `.app`, `.bin`, `.desktop`, `.run`) alongside Windows extensions in `BLOCKED_EXTENSIONS`.
- [cross-platform-hardening, task 2] In PyInstaller build specs, virtualenv executables like Deno may be installed under `Scripts/` or available via system `PATH`; candidate resolution ordering `sys.executable.with_name("deno.exe")`, `parent / "Scripts" / "deno.exe"`, and `shutil.which("deno")` guarantees packaging builds succeed across varying virtual environment structures.
- [cross-platform-hardening, task 2] When validating cross-platform external JS runtime paths in yt-dlp test suites, asserting `.endswith(("deno.exe", "deno"))` supports both Windows executables and POSIX binaries seamlessly.
- [cross-platform-hardening, task 2] Automated GitHub Actions release workflows validating distribution files fail pre-build quality gates if a root `LICENSE` file is absent alongside `THIRD_PARTY_NOTICES.md`, requiring explicit project license presence prior to packaging.
- [cross-platform-hardening, task 3] When testing AST static rule validators like `_ast_errors`, paths passed to the validator must be located within the project `ROOT` directory to avoid `ValueError` from `path.relative_to(ROOT)`.
- [cross-platform-hardening, task 3] In Python logging, `RotatingFileHandler` inherits from `StreamHandler`; asserting `type(h) is RotatingFileHandler` or verifying specific handler counts accurately validates console handler omission when `sys.stdout` is `None`.
- [cross-platform-hardening, task 3] Designing concise, parameterized unit tests allows expanding hardening coverage by 14 new tests while maintaining strict compliance with project line budgets (134 lines total, max test function 11 lines vs 35 limit).
- [cross-platform-hardening, task 4] Cross-platform OS-dependent logic (Windows vs Darwin vs Linux binary resolution and desktop notification calls) can be 100% regression-tested on a single host OS runner by monkeypatching sys.platform and subprocess/shutil boundaries in pytest without multi-OS CI virtualization.
